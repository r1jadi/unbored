# Web app architecture

## Stack

| Concern | Choice |
| --- | --- |
| Framework | TanStack Start 1.168 (React 19, SSR) with Vite 8 |
| Routing | TanStack Router, file based, `src/routes/**` |
| Data (client) | TanStack Query for server state, `src/lib/api/client.ts` for the API |
| Styling | Tailwind v4 with design tokens in `src/styles.css` |
| Build output | Nitro, `cloudflare_module` preset (Cloudflare Workers in production) |
| Tests | Vitest + Testing Library (`src/**/*.test.ts(x)`) |

The app lives at the repository root. That is deliberate — moving a working
live app is riskier than leaving it — and the migration path to
`apps/web` is recorded in [decisions/0002](../decisions/0002-web-app-location.md).

## Rendering

* Pages are server rendered; there is no client-only route.
* `src/server.ts` wraps the SSR entry so a catastrophic server error becomes a
  rendered error page instead of an h2 error payload.
* `src/start.ts` installs two request middlewares: an error boundary for the SSR
  path and TanStack's CSRF protection for server functions.
* `src/routes/__root.tsx` decides the shell: full-screen flows
  (`/login`, `/signup`, `/admin`, …) render bare, everything else renders inside
  `AppShell`.

**The UI is approved and frozen.** Colors, typography, spacing, layout,
navigation, cards, glass effects, icons and animations are not to be changed by
backend work. New screens follow the existing token set in `src/styles.css`.

## SEO and indexability

`src/lib/seo.ts` is the single source of truth:

* `SITE_URL` comes from `VITE_PUBLIC_SITE_URL` (default `https://unbored.lol`),
  so moving to another domain is an environment change.
* `isIndexable(pathname)` is an **allowlist**: a route is private until it is
  explicitly listed. Private routes get `robots: noindex, nofollow` from the root
  head and are disallowed in `public/robots.txt`.
* `seo(title, description, options)` returns per-page metadata — title,
  description, Open Graph, Twitter card, optional JSON-LD — for the 27 routes
  that already call it, unchanged.
* `rootSeo(pathname)` adds the canonical link, `og:url`, `og:site_name` and the
  site-level `WebSite`/`Organization` structured data from the matched pathname.
* `public/sitemap.xml` is generated by `scripts/generate-sitemap.mjs` from the
  same allowlist; CI fails when the committed file drifts.

Private areas that must never be indexed: `/admin*`, `/settings*`, `/play*`,
`/results*`, `/notifications`, `/activity`, `/following`, `/likes`, `/saved`,
`/profile`, `/search`, `/onboarding`, and the auth flows.

`/games/<id>` and `/categories/<slug>` now 404 on an unknown id instead of
rendering a fallback page, which removes an unlimited family of duplicate URLs.

## PWA

`public/manifest.webmanifest` (name, standalone, portrait, theme `#16171b`,
192/512 maskable icons) plus `favicon.png`, `apple-touch-icon.png` and the
`apple-mobile-web-app-*` meta tags in the root head. Installability requires a
manifest, a registered service worker, HTTPS and the icon set — the service
worker is **not** part of this foundation and is recorded as remaining work; the
manifest, icons and viewport behaviour are verified today.

## Data flow

Today the UI reads `src/lib/mock.ts`. That stays until the feature that replaces
it is implemented; deleting it now would break the approved UI.

The path a real call takes is already in place:

```
component → src/lib/api/client.ts (apiFetch)
          → /api/v1/<group>  with Authorization: Bearer <supabase token>
          → Go gateway → owning service → Postgres
```

Two rules for the code that replaces the mock layer:

1. **Never send identity.** The token carries the user; a body field naming a
   user is a bug, and the services reject it.
2. **Never read the database from the browser.** The publishable Supabase key may
   be used for auth and storage; domain data goes through `/api/v1`. See
   [decisions/0008](../decisions/0008-browser-data-access.md).

## Performance

What is already true and should be preserved:

* Routes that need no client state render on the server and hydrate once; there
  is no client-side data waterfall for the initial view.
* No new frontend dependency was added in this phase, and `bun.lock` was left
  untouched, so the client bundle is the same size as before the foundation work.
* Recharts is only imported by the admin charts module, which is behind
  `BARE`/admin routes rather than the main feed.
* `apiFetch` has a 15s timeout, `cache: "no-store"` and request-id correlation,
  so a slow API cannot make a screen hang indefinitely.

Known follow-ups (documented, not done): an OG image at 1200×630 instead of the
square icon, a service worker for offline/install, and code-splitting the admin
charts if bundle analysis shows them in the main chunk.
